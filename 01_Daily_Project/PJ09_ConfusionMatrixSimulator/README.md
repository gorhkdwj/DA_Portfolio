## 2. Key Concepts & Understanding

혼동 행렬과 임계값에 대한 깊이 있는 이해를 바탕으로 시뮬레이터를 설계했습니다.

### 2.1. 혼동 행렬 (Confusion Matrix)의 재해석

모델의 예측(Positive/Negative)과 실제 정답(True/False)의 조합으로 이루어진 4가지 지표를 직관적인 '대장금 비유'를 통해 체화했습니다.

* **TP (True Positive):** 홍시 맛이 나서 홍시라 하옵니다. (정답을 맞춤)
* **FP (False Positive):** 홍시가 없는데 홍시라 하옵니다. (1종 오류, 오발탁)
* **TN (True Negative):** 홍시 맛이 안 나 없다 하옵니다. (정답을 맞춤)
* **FN (False Negative):** 홍시가 있는데 없다 우깁니다. (2종 오류, 놓침)

### 2.2. 정밀도(Precision)와 재현율(Recall)의 트레이드오프

비즈니스 목적에 따라 우선시해야 하는 지표가 다름을 경제학적 기회비용과 연결하여 학습했습니다.

* **정밀도 (Precision):** 모델이 긍정이라고 한 것 중 진짜 정답의 비율. $FP$를 줄이는 것이 핵심이며 스팸 필터 등에 중요합니다.
* **재현율 (Recall):** 실제 존재하는 정답 중 모델이 찾아낸 비율. $FN$을 줄이는 것이 핵심이며 암 진단, 사기 탐지 등에 중요합니다.

$$ Precision = \frac{TP}{TP + FP}, \quad Recall = \frac{TP}{TP + FN} $$

### 2.3. 임계값(Threshold)과 도메인 지식

모델은 확률을 반환할 뿐, 최종 판정을 내리는 기준인 임계값은 전적으로 데이터 분석가와 도메인 전문가의 몫임을 이해했습니다. 이는 단순히 수학적 최적화가 아닌, 각 오류가 초래하는 기대 손실(Expected Loss)을 최소화하는 경제적 의사결정 과정입니다.

$$ Expected\;Loss = (Cost_{FP} \times FP) + (Cost_{FN} \times FN) $$

### 2.4. 본질적 성능 지표: ROC 커브와 AUC

임계값의 변화와 무관하게 모델의 순수한 분류 체력(분별력)을 평가하는 지표로 ROC(Receiver Operating Characteristic) 커브와 AUC(Area Under the Curve)를 학습했습니다. 임계값을 움직이는 것은 산등성이 위에서 내 위치를 바꾸는 것일 뿐, 산의 전체 면적(AUC)은 변하지 않음을 확인했습니다.

### 2.5. 임계값 독립성(Threshold-Independence)의 이해

시뮬레이터를 통해 임계값을 변경하더라도 AUC와 AP(Average Precision) 값이 변하지 않는 현상을 관찰하고 그 수학적, 경제학적 원리를 학습했습니다.

* **수학적 원리:** AUC와 AP는 특정 임계값 하나에서의 성능이 아니라, 임계값을 $0$부터 $1$까지 모든 경우의 수로 움직였을 때 나타나는 전체 궤적의 면적입니다. 즉, 이미 모든 임계값에 대한 평가가 종합된 최종 성적표이므로 단일 임계값의 이동에 영향을 받지 않습니다.
* **경제/통계학적 비유(합격 커트라인):** 시험을 치른 학생들(모델의 예측 확률 분포)이 있을 때, 학교 측에서 합격 커트라인인 임계값을 70점에서 80점으로 올린다고 가정해 봅니다. 합격자의 수나 오발탁 비율($TP$, $FP$)은 즉각적으로 변하겠지만, 학생 집단 전체의 본질적인 학업 수준(AUC)이 변하는 것은 아닙니다.

이를 통해 **"임계값은 비즈니스 부서와 타협하여 이동할 수 있는 전략적 위치(Operating Point)지만, AUC와 AP는 분석가가 모델링을 통해 끌어올려야 하는 모델의 고유한 체급"**이라는 점을 명확히 구분하게 되었습니다.

## 3. Simulator Development Journey

학습한 이론을 실시간으로 조작해 볼 수 있는 React 기반의 웹 어플리케이션을 단계별로 구축하고 고도화했습니다.

### Phase 1: 기본 매트릭스 구현

* TP, FP, FN, TN 숫자를 수동으로 입력하면 Precision, Recall, F1-Score가 실시간으로 계산되는 대시보드를 구축했습니다.
* 대장금 비유를 UI에 적용하여 직관성을 높였습니다.

### Phase 2: Gemini API 연동 (AI 시나리오 & 진단)

* LLM을 호출하여 사용자가 입력한 도메인(예: 자율주행, 사기 탐지)에 알맞은 가상의 혼동 행렬 수치를 탑다운(Top-down) 방식으로 생성하는 기능을 추가했습니다.
* 현재 매트릭스 상태를 분석해 주는 AI 코칭 기능을 도입했습니다.

### Phase 3: ROC / PR 곡선 시각화 추가

* 단일 임계값에서 보장할 수 있는 최소 AUC와 AP 면적을 기하학적으로 시각화하여, 모델의 위치(Operating Point)가 성능 곡선 위에서 어디에 해당하는지 파악할 수 있도록 대시보드를 확장했습니다.

### Phase 4: 임계값 슬라이더 및 수학적 시뮬레이션 고도화

사용자가 기준 매트릭스를 설정한 뒤 $0.0 \sim 1.0$ 사이의 임계값 슬라이더를 움직일 수 있도록 기능을 개편했습니다.

#### 🔧 Troubleshooting: 비대칭 확률 분포 모델링

* **[학습 포인트 및 트러블슈팅]:** 초기에는 임계값이 높아져도 정밀도(Precision)가 상승하지 않고 평행선을 그리는 문제가 발생했습니다. 이는 정답과 오답이 동일한 비율로 감소한다고 단순 가정한 수학적 한계 때문이었습니다.
* **[해결]:** 실제 머신러닝 알고리즘의 비대칭 확률 분포를 모방하기 위해 **비대칭 지수 함수(Asymmetric Power Function)**를 도입했습니다. 이를 통해 임계값을 높일 때 오답(FP)이 정답(TP)보다 훨씬 급격하게 곤두박질치도록 모델링하여, 정밀도가 $1.0$을 향해 아름답게 우상향하는 실제 PR 곡선을 구현해 냈습니다.

### Phase 5: Scikit-learn 표준 레이아웃 적용

* 실무 환경(Python, R)과의 호환성을 위해 대장금 비유를 제거하고, scikit-learn 라이브러리가 출력하는 표준 배열 형태([TN, FP], [FN, TP])로 매트릭스 UI 배치를 전면 수정하여 전문가용 툴로 완성도를 높였습니다.

## 5. Setup Guide (API Integration)

본 시뮬레이터는 AI 기반 맞춤 시나리오 및 모델 진단 기능을 위해 Google Gemini API를 사용합니다. 깃허브(GitHub) 등 퍼블릭 환경에 오픈소스 형태로 코드를 배포하거나 개인 로컬 환경에서 구동할 때, 아래와 같이 API 키 보안과 설정에 유의하여 개발을 진행했습니다.

### 5.1. Gemini API 키 발급 및 적용

1. **발급:** Google AI Studio에 접속하여 프로젝트에 사용할 새로운 API 키를 생성합니다.
2. **적용:** 프로젝트 소스 코드(예: `App.jsx`) 상단에 위치한 `apiKey` 변수에 발급받은 키를 삽입하여 로컬에서 AI 기능을 활성화합니다.

```javascript
// 깃허브 업로드용 안전한 상태 (배포 시 형태)
const apiKey = "";

// 로컬 구동용 (개인 테스트 시 형태)
const apiKey = "AIzaSyYourGeneratedAPIKeyHere...";
```

### 5.2. ⚠️ 실무 보안 주의사항 및 아키텍처 한계

* **키 유출 방지:** 개인 API 키가 입력된 상태의 코드를 GitHub 등 퍼블릭 저장소에 커밋(Commit) 및 푸시(Push)해서는 안 됩니다. 악의적인 봇(Bot)에 의한 키 탈취 및 막대한 금전적 과금이 발생할 수 있습니다. 본 시뮬레이터 프로젝트 역시 `apiKey` 값을 비워둔 상태로 깃허브에 업로드하는 방식을 채택했습니다.
* **실무 환경의 대안:** 실제 기업의 상용 서비스 프로덕션(Production) 환경에서는 프론트엔드 코드에 키를 직접 노출하지 않습니다. 대신 `.env` 파일과 같은 환경 변수(Environment Variables)를 활용하여 키를 안전하게 숨기거나, 사용자가 자신의 API 키를 직접 입력하게 하는 BYOK(Bring Your Own Key) 방식, 혹은 백엔드 서버를 경유하여 호출하는 보안 아키텍처를 구성해야 함을 학습했습니다.
